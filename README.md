# Контейнеризация тестового окружения: Развертывание PostgreSQL в Docker Compose

Инфраструктурный учебный проект, полностью посвященный изучению принципов работы Docker, контейнеризации баз данных и настройке взаимодействия локальных приложений с СУБД **PostgreSQL**. В рамках проекта реализована оркестрация базы данных и конфигурация веб-сервиса для работы в гетерогенной среде.

## 🎯 Цели и задачи проекта
* **Освоение Docker & Docker Compose**: написание декларативного сценария `docker-compose.yml` для автоматического развертывания, настройки и изоляции контейнера базы данных.
* **Конфигурация СУБД (PostgreSQL)**: управление переменными окружения контейнера для создания базы данных, инициализации учетных записей администратора (пользователь/пароль) и проброса сетевых портов.
* **Параметризация приложения**: настройка пула соединений (Connection Pool) в файле `application.properties` для перевода целевого сервиса с архитектуры MySQL на PostgreSQL.
* **Инфраструктурная чистота**: строгое ограничение состава репозитория согласно требованиям технического задания.

---

## 🛠️ Архитектура и состав репозитория

В соответствии с условиями задачи, данный репозиторий является изолированным и содержит исключительно конфигурационные файлы и исполняемый артефакт:
1. 📄 `.gitignore` — игнорирование временных файлов ОС и служебных папок.
2. 📦 `db-api.jar` — бинарный артефакт тестируемого веб-приложения (SUT).
3. ⚙️ `application.properties` — конфигурационный файл с параметрами подключения к БД и настройками веб-сервера.
4. 🐳 `docker-compose.yml` — конфигурация для запуска контейнера базы данных PostgreSQL.

## 🚀 Порядок развертывания и запуска окружения

Для корректного запуска системы необходимо строго соблюдать последовательность инициализации сервисов:

### Шаг 1. Запуск СУБД в Docker
Перед стартом приложения необходимо поднять и инициализировать базу данных. Находясь в корневой директории проекта, выполните команду:
```bash
docker-compose up -d
```
*Флаг `-d` запускает контейнер PostgreSQL (на базе официального образа `postgres:13-alpine`) в фоновом режиме. Обязательно дождитесь полной инициализации СУБД и готовности принимать сетевые соединения.*

### Шаг 2. Конфигурация соединения (`application.properties`)
В файле свойств была изменена строка подключения (драйвер изменен с `mysql` на `postgresql`), а также прописаны параметры, полностью совпадающие с переменными окружения из `docker-compose.yml`:
* Ссылка на хост и порт: `jdbc:postgresql://localhost:5432/<имя_БД>`
* Учетные данные: имя пользователя, пароль.
* Порт веб-сервера: по умолчанию зафиксирован как `server.port=9999`.

### Шаг 3. Запуск целевого приложения (SUT)
После того как контейнер с базой данных успешно поднялся, запустите само Java-приложение:
```bash
java -jar db-api.jar
```

## 🧪 Верификация работоспособности окружения

Если контейнер базы данных и конфигурация подключения настроены верно, приложение успешно применит миграции (при их наличии), свяжется с PostgreSQL и поднимет веб-сервер на порту `9999`.

Для проверки корректности интеграции выполните HTTP GET-запрос (через браузер, Curl или Postman):
* 🔗 **`http://localhost:9999/api/cards`**

*Критерий успешности*: Сервер должен вернуть статус-код `200 OK` и валидный JSON-ответ со списком банковских карт, успешно извлеченных из СУБД PostgreSQL.
